Qualité des données INSEE

Ce qu'on a téléchargé chez l'INSEE, et les 8 problèmes à corriger avant de s'en servir. Cette page part de zéro : aucune connaissance préalable des données n'est nécessaire.

4 419 302 lignes · 10 939 communes · 1,7 Go · Île-de-France, Bretagne, Occitanie, Auvergne-Rhône-Alpes

1. De quoi parle-t-on ?

L'INSEE est l'institut public de la statistique. Il publie, commune par commune, des chiffres sur les habitants et les logements : combien de personnes, de quel âge, avec quels revenus, dans quels logements. On les récupère par une adresse internet que l'INSEE met à disposition gratuitement, appelée API Melodi, qui renvoie les chiffres sous forme de fichiers texte.

Dans notre projet, ces chiffres servent à décrire le quartier autour d'un bien vendu. DVF nous dit à quel prix un logement s'est vendu ; l'INSEE nous dit si la commune est riche ou pauvre, jeune ou familiale. Le lien entre les deux se fait par le code de la commune, un numéro à 5 chiffres (Rennes = 35238).

À quoi ressemble une ligne

Les fichiers ne sont pas des tableaux : chaque chiffre arrive seul, accompagné de ses étiquettes. Voici une vraie ligne, celle du revenu médian de Rennes.

{
  "dimensions": { "GEO": "2026-COM-35238", "TIME_PERIOD": "2023",
                  "FILOSOFI_MEASURE": "MED_SL", "UNIT_MEASURE": "EUR_YR" },
  "attributes": { "OBS_STATUS": "A", "CONF_STATUS": "F" },
  "measures":   { "OBS_VALUE_NIVEAU": { "value": 25100 } }
}
GEO
De quel territoire on parle : ici la commune 35238, Rennes. Le 2026 est l'année de la carte des communes utilisée.
TIME_PERIOD
L'année du chiffre : 2023.
FILOSOFI_MEASURE
Le sujet mesuré : MED_SL veut dire revenu médian.
UNIT_MEASURE
L'unité : des euros par an. Ailleurs ce sera un pourcentage ou un nombre de personnes.
OBS_STATUS
Un code qui dit si le chiffre est publié ou non.
value
Le chiffre lui-même : 25 100.

Une ligne = un territoire, un sujet, une année, une valeur. Il faut donc reconstituer un tableau à partir de ces lignes avant de pouvoir s'en servir : c'est le travail du passage en silver.

3. Le détail

01

Les données de revenus sont presque toutes vides

Critique
En clair
Le fichier des revenus (Filosofi) annonce 27 sujets : revenu médian, taux de pauvreté, écarts entre riches et pauvres, origine des revenus… Mais 25 de ces 27 sujets n'ont aucun chiffre pour les communes. Les cases existent, elles sont vides.
Pourquoi
L'INSEE ne publie ces 25 sujets qu'à des échelles plus grandes, comme le département ou la région.
Conséquence
Sur l'argent, il ne nous reste que deux chiffres par commune : le revenu médian (disponible pour 9 658 communes) et le taux de pauvreté (2 233 communes).
Correction
Ne garder que ces deux chiffres et supprimer les 25 colonnes vides, qui ne se rempliront jamais.
02

Paris, Lyon et Marseille n'ont aucune donnée

Critique
En clair
Ces trois villes sont découpées en arrondissements. DVF enregistre les ventes par arrondissement (Paris 15ᵉ = 75115), alors que l'INSEE publie ses chiffres pour la ville entière (Paris = 75056). Les deux ne se rencontrent jamais.
Conséquence
5 % des ventes se retrouvent sans aucune donnée INSEE, et ce sont justement les endroits où il se vend le plus : 3 790 ventes dans le 15ᵉ, 3 334 dans le 16ᵉ, 3 292 dans le 18ᵉ.
Correction
Avant de rapprocher les deux sources, remplacer le code de l'arrondissement par celui de sa ville. La couverture passe de 95 % à près de 100 % des ventes. 
751xx  → 75056   (Paris)
6938x  → 69123   (Lyon)
132xx  → 13055   (Marseille)
03

On n'a téléchargé qu'une seule année

Critique
En clair
Tous nos fichiers ne contiennent que l'année 2023, parce que le téléchargement a été limité à cette année. Or le fichier des populations en propose 23, de 1968 à 2023.
Conséquence
Avec une seule année, on ne peut mesurer aucune évolution. On ne peut donc pas répondre à la question du client : quelles communes sont en train de monter, pour y ouvrir la 6ᵉ agence.
Correction
Relancer le téléchargement des populations sans limiter l'année. Le fichier pèse 3 Mo et donne l'évolution de la population sur 55 ans.
04

Un chiffre peut manquer pour deux raisons différentes

Attention
En clair
Quand une case est vide, l'INSEE indique pourquoi, par un code. Il y a deux cas, et ils ne veulent pas dire la même chose : 273 435 cases portent le code O : le chiffre n'existe pas à l'échelle de la commune ; 9 973 cases portent le code C : le chiffre existe, mais l'INSEE le cache pour protéger l'anonymat des habitants, car la commune est trop petite.
Conséquence
Si on mélange les deux, le rapport de qualité est faux : dans un cas la donnée n'existe pas, dans l'autre elle est seulement protégée.
Correction
Garder les deux codes et les compter séparément.
05

Le taux de pauvreté manque à la campagne

Attention
En clair
Le taux de pauvreté n'est publié que pour les communes assez peuplées. Il existe pour 20,7 % des communes où il y a eu des ventes, mais comme ce sont les villes, cela représente quand même 54,7 % des ventes.
Conséquence
Utilisable en ville, inutilisable en zone rurale.
Correction
Ne s'en servir que pour les analyses urbaines, et toujours afficher sur combien de communes le calcul porte.
06

Un fichier utilise une autre carte des communes

Attention
En clair
Les communes fusionnent, changent de nom, de code. Chaque fichier précise donc l'année de la carte qu'il utilise, collée devant le code de la commune. Six fichiers utilisent la carte 2026, celui des populations utilise la carte 2025. 
2026-COM-35238   six fichiers
2025-COM-35238   fichier des populations
Conséquence
Si on rapproche les fichiers en comparant le code tel quel, rien ne correspond, puisque le début diffère.
Correction
Découper le code en trois morceaux et ne garder que le numéro de la commune (ici 35238).
07

Un chiffre absent ne s'écrit pas comme prévu

Technique
En clair
Quand un chiffre manque, l'INSEE n'écrit pas « vide » : il écrit une case contenant… rien du tout, {}. La case est donc bien là, mais elle ne contient aucune valeur. 
"OBS_VALUE_NIVEAU": {}                 chiffre absent
"OBS_VALUE_NIVEAU": { "value": 25100 } chiffre présent
Conséquence
Un programme qui vérifie seulement que la case existe conclut que tout est rempli à 100 %, alors que Filosofi n'est rempli qu'à 4 %.
Correction
Vérifier la présence du mot value à l'intérieur de la case, et non la case elle-même.
08

Les fichiers n'ont pas tous la même forme

Technique
En clair
Le nombre d'étiquettes accompagnant chaque chiffre change selon le fichier : 4 pour les revenus, 13 pour les logements (type de logement, nombre de pièces, époque de construction, chauffage, stationnement…). Le nom de l'étiquette qui porte le sujet change aussi d'un fichier à l'autre, et le fichier des populations n'a carrément aucune étiquette de statut.
Conséquence
Un programme écrit pour un fichier plante ou perd des colonnes sur un autre.
Correction
Lire les étiquettes présentes au lieu de les supposer connues, et créer un tableau par fichier plutôt qu'un tableau unique.

4. Ce qui va bien

  • Les 5 fichiers du recensement sont remplis à 100 % : habitants, ménages, logements, emploi, diplômes. Aucune case vide.
  • Ils couvrent 99,5 % des communes où il y a eu des ventes, soit 95 % des ventes.
  • Aucun doublon : aucune ligne n'a été téléchargée deux fois.
  • Aucun morceau manquant : le téléchargement s'est fait par paquets, et chaque paquet a été vérifié.
  • Tous les chiffres sont au niveau de la commune, qui est exactement ce dont on a besoin pour les relier à DVF.

5. À faire avant la suite

  1. Rattacher les arrondissements à leur ville, pour récupérer 5 % des ventes.
  2. Retélécharger les populations sur toutes les années, pour pouvoir mesurer les évolutions.
  3. Découper le code du territoire et ne garder que le numéro de la commune.
  4. Supprimer les 25 colonnes de revenus vides, garder le revenu médian et le taux de pauvreté.
  5. Transformer les lignes en tableaux, un par fichier, en conservant les codes qui expliquent les cases vides.
